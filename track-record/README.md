# Prospective track record

The prospective record begins on **17 August 2026**. It currently contains **zero completed formal forecasts**, so there are insufficient observations for performance conclusions.

Wix, Snap, Amplitude, and IREN are part of the repository's retrospective [origin story](../README.md#why-this-exists). Those original calls are deliberately excluded from prospective statistics because the research was not registered here before the outcomes. A later, genuinely prospective update on one of those companies may enter the ledger only after satisfying the current publication and chronology gates; the 21 August 2026 Snap re-underwrite remains an unregistered draft.

## Records

- [`forecast-ledger.csv`](forecast-ledger.csv): append-only index of formal company theses; `validate-company-ledger` checks structure, chronology, target order, origin-matched commit links, and committed thesis/identity consistency, but automated adjusted-return scoring is not implemented
- [`event-forecast-ledger.csv`](event-forecast-ledger.csv): append-only index of independently resolvable event-outcome and security-reaction forecasts, with identity, baseline, evaluation-spec, forecast-commit, and outcome-commit linkage
- [`event-candidate-ledger.csv`](event-candidate-ledger.csv): all identified event candidates and registered, abstained, ineligible, or deferred decisions for declared-cohort coverage and selection-bias audits; first-appearance Git history is immutable and registered forecasts point back to it
- [Decisions](decisions/README.md): dated buy, add, reduce, exit, watch, or pass records when disclosed
- [Retrospectives](retrospectives/README.md): thesis, outcome, and process reviews
- [Performance policy](../methodology/PERFORMANCE_AND_DISCLOSURES.md): inclusion, benchmark, scoring, and disclosure rules

## Provenance

Each formal forecast should link to the public commit that first published it. Event outcomes must link to a separate public commit containing the validated outcome record. Published initial theses and material updates should not be force-pushed away or silently rewritten. Releases or signed tags may later provide stronger checkpoints around major publications.
